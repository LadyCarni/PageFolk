# The Long List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add The Long List, where members suggest books and vote on them. Add a Bookshelf nav menu that groups it with Our shelf. Give the admin a "Choose this book" action that turns a suggestion into a club book.

**Architecture:** Two new Prisma models, `LongListBook` and `LongListVote`, kept separate from `Book`. Pure helpers for sorting, ranking, duplicate keys and copy go in `src/lib/long-list-view.ts`. Database work goes in `src/lib/long-list.ts`. Server actions in `src/app/long-list/actions.ts` wrap it. The page copies the Our shelf pattern (`ShelfBrowser.tsx`): a list with a side panel at lg and up, and a separate page per book on narrow screens.

**Tech Stack:** Next.js 14 App Router, Chakra UI v2, Prisma on SQLite (schema is applied with `prisma db push`; there are no migrations), Auth.js JWT sessions, and Vitest against a real test DB (`npm test` resets it).

**Spec:** `docs/superpowers/specs/2026-11-10-long-list-design.md`. Read it alongside this plan. The mockups it names show the chosen row (option C) and panel (option E).

## Global Constraints

- Routes: `/long-list` (list; query `?sort=votes|newest|az` and `?book=<id>`) and `/long-list/<id>` (one book, for narrow screens).
- Nav: **Bookshelf** replaces **Our shelf**. It is a dropdown with **Our shelf** (`/shelf`) and **The Long List** (`/long-list`). Order: This month, Bookshelf, Members, What's new, Admin.
- Limits: title ≤ 200, author ≤ 200, synopsis ≤ 300 characters (after trimming). Title, author and synopsis are required. Genre is optional, from `GENRES`.
- Validation copy, exactly: "Add a title", "Add an author", "Add a short synopsis", "Title must be 200 characters or fewer", "Author must be 200 characters or fewer", "Synopsis must be 300 characters or fewer". For genre, use `validateGenre`'s own message.
- Duplicate copy, exactly:
  - Long List: "That book is already on the Long List", linking to `/long-list?book=<id>`.
  - Past `Book`: "The club has already read that one", linking to `/shelf/<id>`.
  - Current `Book`: "That's the club's current book", linking to `/`.
  - Upcoming `Book`: "That one's already lined up for the club", with no link.
- Gone-book copy: "That book is no longer on the Long List". It's a `ValidationError`.
- Ownership: the person who suggested a book, or the admin, may edit or delete it. Anyone else gets a thrown `Error('Forbidden: not your suggestion')`, not a validation message.
- Button copy:
  - "Suggest a book"
  - "Add to the Long List" (create submit)
  - "Save changes" (edit submit; modal title "Edit suggestion")
  - "Cancel"
  - "Vote" / "✓ Voted"
  - "Edit"
  - "Delete my suggestion" (owner) / "Delete" (admin, not owner)
  - "Choose this book" (admin)
- Delete confirmation: "Remove *Title* from The Long List? Its votes will be removed too."
- Choose modal prompt: "How many chapters does *Title* have?"
- Colours and type: use the theme tokens from the mockups:
  - title: `parchment`, heading font
  - secondary text: `mist`
  - genre pill: `dustyRose` text, `border` outline
  - voted button: `antiqueGold` fill, `onGold` text
  - selected row: `bubbleMine`
  - panel: `panel` bg with `divider` left border
- Never run `npm run build` while the dev server is running (it breaks the dev server). Verify UI with the dev server only.

## Review Focus

1. **A double-tapped vote.** It must end up as exactly one vote or none, never an error and never two. *Pinned in Task 2 (`toggleLongListVote` race test).*
2. **Acting on a book that has just been deleted or chosen** (stale page: vote, edit, delete). The member should get "That book is no longer on the Long List", not a crash. *Pinned in Task 2.*
3. **Duplicate checks with messy input**, such as "  the  REMAINS of the day " against "The Remains of the Day". These must be caught. *Pinned in Task 1 (`duplicateKey`) and Task 2.*
4. **Editing a suggestion without changing its title.** It must not count as a duplicate of itself. Editing it to match a different book still must. *Pinned in Task 2.*
5. **A non-owner calling the edit or delete action directly** (bypassing hidden buttons). It must be rejected with nothing changed. *Pinned in Task 4.*

    - With `book`: edit mode. Title "Edit suggestion", submit "Save changes", with a hidden `id` and the fields prefilled.
    - Fields: Title, Author, Genre (`Select` with a first option "No genre" = `''`, then `GENRES`), and Synopsis (a `Textarea` with a live "n / 300" counter and the placeholder "A sentence or two about the book.").
    - Inputs carry `maxLength` set to the limits.
    - A returned `error` shows under the form. If `href` is present, a "See it" link to `href` is added after it.
    - After a successful create, close the modal and navigate to the new book. At lg (`WIDE_QUERY`) that's `router.push('/long-list?book=<id>')`; otherwise `router.push('/long-list/<id>')`.
    - After a successful edit, close the modal and call `router.refresh()`.
  - `SuggestionActions({ book, viewerId, isAdmin, onPhonePage }: { book: LongListEntry; viewerId: string; isAdmin: boolean; onPhonePage: boolean })`
    - Renders nothing unless `book.canEdit` or `isAdmin`.
    - Edit opens `SuggestionModal`.
    - Delete ("Delete my suggestion" if the viewer is the owner, otherwise "Delete") opens a Chakra `AlertDialog` with the exact confirmation copy. After deleting, it goes to `router.push('/long-list')` on the phone page and `router.refresh()` otherwise.
    - For the admin, it adds a dashed `borderMuted` divider labelled "Admin" in `dustyRose`, and **Choose this book**, which opens `ChooseBookModal`.
  - `ChooseBookModal({ isOpen, onClose, book })`
    - A number input named `totalChapters` (min 1) and a hidden `id`, under the exact prompt copy.
    - Submits to `chooseLongListBookAction`. A returned `error` shows inline; on success, the action redirects.
- In both pages, `SuggestButton` (gold "Suggest a book", which opens the create modal) sits on the header row, including in the empty state.
